# HyperCeiler 重构与独立维护指南

适用于 `refactor/prune`。以分支现有行为和本地证据为准，不以追齐上游为目标。当前风险与续查位置见[范围台账](refactor-scope-audit.md)。

## 不可破坏的边界

- **兼容性**：保留 pudding、liuqin、HyperOS 3/4、SDK 36/37 已验证的行为和有效回退；维持 `compileSdk 37`、`minSdk 35`、`targetSdk 37`。单个 ROM 缺类、空壳包或目录无显式引用，都不足以退役功能。
- **跨端契约**：保留 HCS1、HCY1、HCL4 和 Weather HWS1 的 ABI 与 wire 协议；跨端核对调用者、版本、长度、偏移及拒绝响应。保留 generation、ticket、revision、deadline 的发布检查和热重载清理。
- **后台工作**：Provider 只响应实际需求，不恢复普通桌面的全局预取、固定周期查询或失败自续命。通知只标记失效；查询失败保留适用的 last-good 数据，但授权失败关闭。
- **最近任务与窗口**：状态栏授权同时依赖有效观察、当前 publication 和 Insets 判定，保留 Overview、焦点、可见性及锁屏约束。Binder 回调不为取场景获取 WMS 全局锁；Surface lease 以实际提交和回调退出为恢复依据，不用固定超时代替。
- **操作范围**：只用仓库、已有脱敏材料和离线工具；不联网补证、不联系第三方、不推送、不创建 PR、不触发远端 CI、不操作设备。不读未经授权的凭据或真实签名配置，不全局安装或强制清理。

## 怎样推进

1. 优先处理授权、协议、恢复和常驻开销，再看交互与冷路径。先查真实装载、调用方和回退；有可复现缺陷或明确收益才改生产代码，没有证据就记下重审条件。
2. 选最小改动：消除无消费者的工作，去掉同次回调的等价查询，或按资源所有者收束生命周期。明确缓存失效、异步发布和回退，不为局部问题另建共享框架。
3. 复用已有检查，只长期保留能捕捉独有且重要回归的用例（如授权、跨端协议、资源生命周期和失败恢复）。规则摸底、历史版本对照、源码变异和只在修改时需要的核对按需临时执行；宿主夹具不等于 ROM 命中、真机表现或性能证据。
4. 按独立逻辑单元核对暂存差异、运行相应检查并本地提交，格式 `<type>(<scope>): <简练中文描述>`。一次性命令、计数和通过记录留在提交中；长期文档只维护仍影响决策的边界和未决事项。

## 本地验证与产物

依照[测试可移植性说明](../tests/PORTABILITY.md)选择既有 JDK、SDK、NDK 和离线缓存。先检查 runner 的命令与输出位置；Gradle 使用 `--offline`，调用 wrapper 前确认发行版已缓存。缺少输入就记录受阻，不联网补齐或修改签名与 SDK 配置求通过。

临时夹具和编译输出放独立临时目录，用完清理；交付产物同类只保留最新可用的一份。不动用户已有文件和共享缓存，不另存 APK、报告或备份。

历史验证按提交查阅：`git log --oneline 0eea526d1..HEAD`；首批记录见 `git show e5594b98d:docs/refactor-audit.md`，旧台账见 `git show 8521a886b^:docs/refactor-scope-audit.md`。历史结果不计入当前回归覆盖。
